1. What Framing is

Framing is the application architecture: the React/TypeScript structure, how screens are nested, and which modules are allowed to own data. This inspection found a coherent city-and-district frame. It also found a second, newer frame (the service/provider seam) sitting in front of the older one, only partly connected to the walls.

PRD mismatch — Framing of the lots

The PRD names Construction Exchange, Residential, and Commercial. The registry names Contractor, and has no Residential or Commercial lots. Real Estate is early access, not a homeowner flow. A second live district should be a new parallel folder/layout, not a generic rewrite of Media & Technology, unless the Owner explicitly orders that refactor. That rule is already written in the project’s own architecture file.

Framing risk

Two generations of the same walls. The new seam is real code, with tests, but most of the Rooms people actually walk through still nail into the old studs. Flipping a VITE_*_PROVIDER=supabase flag today would not move Board, Handshake, or Messages onto the Foundation — those screens never call the seam. Auth is the exception, and that exception is dangerous (see 03).

8. Core Rooms as framed today

Veil (24-hour default)

visibilityPlans.ts defines Free Daily VAEL at 24 hours. visibilityLifecycle.ts sets DEFAULT_DURATION_HOURS = 24. New listings in mockListings.ts receive expiresAt at creation. The board filters with isLifecycleVisible(). Re-veil reconciles open connections via mockConnections.reconcileConnectionsAfterReVael. Extended plans are catalog + demo checkout only.

Matching Board

src/lib/matching.ts scores offering vs seeking listings. Weights (when applicable, sum 100): Discipline 22, Skills 10, Tools 9, Certifications 6, Location 10, Remote/Onsite 6, Timing 11, Experience 9, Engagement 6, Budget proxy 5, Completeness proxy 6. Bands: Strong ≥80, Good ≥60, Possible ≥40. This engine is Media & Technology’s, not a city-wide engine. It is a protected file — do not change weights without Owner confirmation.

Handshake Room

Unified model in mockConnections.ts: source is board_match or handshake; status pending / declined / connected / closed. Full profiles and chat live on the connection detail screen after mutual accept. connectionService exists and is unused by pages.

Profiles

ProfileDetails holds headline, bio, disciplines, skills, tools, location, rates, portfolio links, team. License, insurance, capability statement, and related credentials live on the documents tab (DOC_TYPES in docTypes.ts), not as first-class columns on the profile record. Completeness is a heuristic, not a verified-identity workflow.

Community

City homepage and /feed mix community cards with listings via homeFeed.ts. District community lives at /media-technology/community. Both go through communityService for posts/saves. Sample/demo posts are local-only by design.

9. Protected framing (do not casually restud)

Observed pattern across prior stages, not a mechanical lock: matching.ts, Board.tsx sort order, LiveExchangeDemo.tsx, and the Extended VAEL page set. Confirm with the Owner before changing them. private/patent is gitignored and must not be created or referenced.

10. Inspections (as designed in this repo)

The project’s own verifier (dev-agent/verify.mjs) documents a vitest baseline of 586 tests / 57 files and exactly 7 TypeScript errors that are treated as a known fingerprint, not a license to add more:

  • 3 in src/data/listings.ts — dead Supabase client possibly null / never[]
  • 2 in vite.config.ts — Node path / __dirname types
  • 2 in vitest.config.ts — same

This audit copy of the workspace had no .git directory and no successful npm install during the inspection window, so those commands were not re-run here. The fingerprint above is what the repository itself claims. A fresh clone with dependencies should re-confirm before Milestone 2 starts.

11. Framing verdict

Keep the frame

City shell + one live district + mock ownership + protected matching is a sound continue-don’t-rebuild Framing. The unfinished work is (a) connecting the new service seam to the Rooms people already use, and (b) adding PRD districts as new parallel Rooms, not by melting Media & Technology into a generic blob.
