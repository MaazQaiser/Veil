1. How to read this list

Items are gaps between the PRD’s City and this repository. They are not all bugs. Many are unfinished Rooms. Owner decisions are called out so engineering does not invent policy.

BadgeMeaning
Blocks productThe City cannot function as the PRD product for real users until this is faced (usually Foundation + identity).
Blocks a PRD RoomA named Milestone 2/3 deliverable does not exist or does not work as specified.
Owner decisionNot an engineering default. Wait.
Stabilize / polishPrototype works; seam, docs, or hygiene should be cleaned before or during cutover.

Milestone tags: M2 core + Construction + Trucking · M3 Residential / Commercial / Communities · M4 harden / docs / handoff. Change Orders stay out of these tags.

2. Blocks the product as a real City

PL-001

Runtime Foundation is browser storage, not a shared database

Blocks product M2+

Two users cannot share a Handshake, listing, or message across devices. This is the prototype’s nature, not a crash. It is still the reason the City is not yet the product for a real market.

src/lib/mock*.ts · src/integrations/supabase/client.ts (supabase = null) · supabase/README.md

PL-002

Auth cutover would authenticate people and then lose them

Blocks product M2

Handle claim, join profile-type, waitlist, team search, and admin rosters still read mockAuth by user id. A real Auth uuid is not in that book. isAdmin would be hardcoded false.

HandleClaimGate.tsx · ClaimHandleDialog.tsx · JoinNetwork.tsx · supabaseAuthProvider.ts:64-70 · Document 03

PL-003

VAEL / Handshake / messaging seams are built and not attached to the walls

Blocks product M2

Board, VaelFlow, Connections, ConnectionDetail, Messages, notification bell still nail into mock modules. Flipping provider flags is a no-op for those Rooms. A later “just connect Supabase” would not move the product.

src/lib/authority/registry.ts WIRED_INTO_UI · mockVaelProvider / mockConnectionProvider headers

PL-004

Foundation drawing cannot store the listing body people already type

Blocks product M2

vaels has side, category, discipline, location, plan, expiry — not description, contact, requirements, budget, timeline. The Supabase provider accepts richContent and never sends it. Re-veil reconciliation has no SQL function (returns empty arrays).

supabaseVaelProvider.ts:11-24 · supabaseConnectionProvider.ts reconcileAfterRevael · 0003_vael_foundation.sql

PL-005

No file Utility — documents and chat attachments cannot live on the Foundation as-is

Blocks product M2

Media stays pending; nothing marks stored; storage disabled in config. Document bytes exist only as local data URLs. Messaging provider returns no attachment ids. Block checks on send exist in mock messaging and not in the Supabase messaging provider (safety gap if wired).

supabaseMediaProvider.ts:11-23 · supabaseDocumentsProvider.ts:6-11 · supabaseMessagingProvider.ts:137-140 · notificationChannels.ts

PL-006

Matching engine is Media & Technology only

Blocks product M2

Percentage fit is real for editors/developers/studios. Construction and Trucking cannot reuse those weights honestly (tools, certifications, media disciplines). matching.ts is protected — district-specific engines or an Owner-approved generalization is required before those Boards are “the same Room.”

src/lib/matching.ts · src/lib/requirements.ts · CLAUDE.md §2
